# 需求理解

| 项目 | 定义 |
|---|---|
| 用户 | 运营人员：给出主题、预算、截止时间，想拿到一份能直接用的内容活动方案 |
| 方案的定义（本项目解读） | 一份保存下来的包：引用的素材 id、一份主脚本（必需）、可选的其他脚本（如预热），以及总费用与总工时。题目未定义"方案"的形态，这是我们按四个工具与交付要求推出的 |
| 价值假设 | 把"在约束内拼出一份方案"的规划与反复试错交给 Agent；尚未测量业务收益 |
| 输入 | `topic`、`budget`（模拟单位）、`deadline`；可选 `request_id`、`now`（测试时钟）、`quality_preference` |
| 材料 | `data/materials.json` 12 条合成素材（只有描述与标签）；`data/cost_table.json` 工具费用与工时 |
| 工具 | 素材检索、脚本生成、成本估算、方案保存（业务）+ 拟计划、改计划、结束（规划） |
| 输出 | 任务计划、步骤状态、工具结果、费用合计（已花 / 剩余 / 预计总额）、已保存方案或未完成原因、调整说明、一句面向运营的结论 |
| 范围 | 本地 CLI、合成数据、SQLite 持久化、真实模型（百炼 qwen-plus）与离线 Mock |
| 不包含 | 联网检索真实素材、真实视频生成、HTTP 服务、多用户并发、模型生成脚本正文（当前为确定性模板） |
| 基础验收 | 正常完成；缺预算 / 缺截止时间；工具失败；预算超限；重复执行；（加分）失败步骤续跑 |
| 效果边界 | 预算与工时都是模拟单位，不是真实价格或生成延迟；脚本由模板拼成，不评估内容质量 |

## 关键约束的取舍

- **预算与截止时间各自是硬约束**。没有"允许超预算"开关：估算或执行会超限时，由模型改计划或停止，代码只负责拒绝。
- **预算不够不是报错**。能降级就降级，并在终报里说明"原方案预计多少、改了什么、现在多少"；连最低交付（一次搜索 + 一份简版主脚本）都做不到时，返回未完成与缺口，并给出建议。
- **失败不计费、不推进时钟**（MVP 假设，便于核对账目）。
- 预算指的是业务模拟费用；模型 API 的 token 用量另行记录在终报 `llm_usage`，不混入预算。
