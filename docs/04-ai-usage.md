# AI 使用说明

本项目在 Claude（Anthropic）辅助下完成。题目允许 AI 辅助；本页按**思路与决策的来源**记录贡献，不按谁敲的键盘：设计判断、取舍、纠错由我做出并对结果负责，代码与文档初稿由 AI 按我的决定生成，再由我审阅、运行与验证。不附完整聊天记录。

## 分工

| 阶段 | 我（Henry）做的 | AI 做的 | 验证方式 |
|---|---|---|---|
| 选题与理解 | 读四道题，决定只做题二；追问并纠正 AI 对业务场景的误读（最初把题目理解成"双11 剪辑模板推广的配音/剪辑流程"，实际工具只有搜素材、写脚本、估算、保存） | 四题比选分析；按我的纠正重写场景理解 | 对照题目原文逐条核对（`markingRubric` §1） |
| 设计 | 拍板关键取舍（见下表）；把设计 v1 交给另一个模型（GPT）评审，再把评审意见拿回来讨论采纳 | 起草设计文档 v1 → v1.1；整理 GPT 评审的 11 条意见并逐条给出采纳/保留理由 | 设计文档 §21 记录否决与保留项 |
| 代码 | 决定最小实现范围；决定提交规范（提交信息简洁、信息密度高）；在本机运行真实模型 | 在云端沙箱按设计编写 `src/` 与 `tests/`，离线跑通 11 个场景 | `pytest -q` 62 项；`examples/mock/` 11 个场景产物 |
| 真实模型验证 | 本机配置密钥与 uv 环境，运行 normal / tool_failure_once / over_budget，反馈结果 | 读 trace 核对状态、费用、五要素 | `examples/<场景>/` 真实产物；`docs/03` 用例表 |
| 文档 | 审阅与修改 | 起草 README 与 docs/01–05 | 对照 `markingRubric.md` 85 行逐项核对 |

## 边界

- 真实模型（qwen-plus）的决策过程全部来自本机运行的真实 trace，没有用 Mock 冒充；`examples/mock/` 单独存放并标注。
- AI 生成的代码我没有逐行全部验证；验证依据是测试、离线场景与真实运行结果，见 `docs/03-evaluation.md`。
- 本页不能单独证明个人贡献；设计讨论中的提问与纠错是我理解程度的主要体现。
