# AI 使用说明

本项目在 Claude（Anthropic）辅助下完成。题目允许 AI 辅助；本页按**思路与决策的来源**记录贡献，不按谁敲的键盘：设计判断、取舍、纠错由我做出并对结果负责，代码与文档初稿由 AI 按我的决定生成，再由我审阅、运行与验证。不附完整聊天记录。

## 分工

| 阶段 | 我（Henry）做的 | AI 做的 | 验证方式 |
|---|---|---|---|
| 选题与理解 | 读四道题，决定只做题二；追问并纠正 AI 对业务场景的误读（最初把题目理解成"双11 剪辑模板推广的配音/剪辑流程"，实际工具只有搜素材、写脚本、估算、保存） | 四题比选分析；按我的纠正重写场景理解 | 对照题目原文逐条核对（`markingRubric` §1） |
| 设计 | 拍板关键取舍（见下表）；把设计 v1 交给另一个模型（GPT）评审，再把评审意见拿回来讨论采纳 | 起草设计文档 v1 → v1.1；整理 GPT 评审的 11 条意见并逐条给出采纳/保留理由 | 设计文档 §21 记录否决与保留项 |
| 代码 | 决定最小实现范围；决定提交规范（提交信息简洁、信息密度高）；在本机运行真实模型 | 在云端沙箱按设计编写 `src/` 与 `tests/`，离线跑通 11 个场景 | `uv run pytest` 92 项；`examples/mock/` 11 个场景产物 |
| 真实模型验证 | 本机配置密钥与 uv 环境，运行 normal / tool_failure_once / over_budget / over_budget_b / resume（持续故障后 `--resume`），反馈结果；11-11 在最终候选源码上跑两轮复验（各 5 条） | 读 trace 核对状态、费用、五要素 | `examples/<场景>/` 真实产物；`docs/03` 用例表 |
| 文档 | 审阅与修改 | 起草 README 与 docs/01–05 | 对照 [acceptance-checklist.md](acceptance-checklist.md) 85 行逐项核对 |

## AI 产出中我亲手修改的地方

| 位置 | 原来 | 我改成 | 为什么 | 验证 | 提交 |
|---|---|---|---|---|---|
| `src/loop.py` 动作额度提醒 | 只在剩最后 1 次动作时提醒模型，文案只说"如无法完成请以 incomplete 结束" | 提前到剩 3 次时提醒，文案加上"刚好够估算、保存、结束" | 正常收尾需要 3 个动作（估算、保存、结束），剩 1 次才提醒已来不及保存；11-10 的真实续跑实验里模型把 15 次动作用光、什么都没保存 | 本机 `uv run pytest` 80 项通过 | `c0eb18b` |

取舍：只在恰好剩 3 次时提醒一次（之后不再重复），换来实现简单、文案里的数字恒为真；尚未用真实模型验证提醒是否改变其行为。

## 边界

- 真实模型（qwen-plus）的决策过程全部来自本机运行的真实 trace，没有用 Mock 冒充；`examples/mock/` 单独存放并标注。
- AI 生成的代码我没有逐行全部验证；验证依据是测试、离线场景与真实运行结果，见 `docs/03-evaluation.md`。
- 本页不能单独证明个人贡献；设计讨论中的提问与纠错是我理解程度的主要体现。
